# Contributing to Spunky Tensor

Read the project's README and local contribution instructions first.
Local instructions take precedence over these shared defaults.

- Search existing issues before you submit a bug or proposal.
- Use the affected repository's security policy and private reporting route for vulnerabilities.
- Keep exploit details, credentials, and private data out of public issues and pull requests.
- Keep each pull request focused.
- Explain the change, its reason, and the checks.
- Identify checks you cannot run.
- Add regression tests for behavior changes.
- Verify equivalent or stronger coverage before you replace security checks.
- Document the origin, version, license, and attribution for each third-party component or asset.
- Include required notices in distributions.
  An upstream license link alone can fail license requirements.
- Keep credentials and personal data out of commits.
- Commit build outputs only when the project's process requires them.

Contributions must comply with the project's license.
These guidelines preserve that license and require no separate contributor agreement.
