# Contributing to Spunky Tensor

Read the project's README and local contribution instructions first. Project-local
instructions take precedence over these shared defaults.

- Use issues for reproducible bugs and focused proposals. Search existing issues
  before opening a new one.
- For security vulnerabilities, use the affected repository's security policy and
  private reporting route. Do not post exploit details, credentials, or private
  data in a public issue or pull request.
- Keep pull requests focused. Explain the behavior being changed, the reason, and
  the checks you ran. Identify checks you could not run.
- Add regression coverage for changed behavior. Preserve existing security checks
  unless equivalent or stronger coverage has been verified.
- For dependencies, vendored code, fonts, images, or model assets, document origin,
  version, license, and required attribution. Include required notices in the
  distribution; a link to an upstream license may not satisfy its terms.
- Do not commit credentials or personal data. Keep generated build outputs out of
  source control unless the project's documented process requires them.

Contributions must be compatible with the affected project's license. These
guidelines do not change that license or require a separate contributor agreement.
